# Creativity rewards in DiffusionNFT

## Scope

This repository ports the full RAM creativity reward module into DiffusionNFT. The
original NFT trainer remains unchanged. Creativity runs use the dedicated
`scripts/train_nft_creativity_sd3.py` entry point.

The port supports IEM, CLIP cosine/L2, DINO cosine/L2, TPIPS overall, same-prompt
and diverse references, nearest-reference selection for image distances, and
weighted multi-metric rewards. The first experiment enables only IEM.

## Frozen baseline and trainable policy

The CFG-distillation LoRA is merged into SD3.5 Medium before NFT's adapters are
created (`scripts/train_nft_creativity_sd3.py:232`). This makes the frozen
baseline exactly `SD3.5M + CFG-distillation LoRA`. DiffusionNFT then adds:

- `default`: the trainable rank-32, alpha-64 LoRA.
- `old`: the lagged rollout-policy LoRA used by NFT.

Disabling PEFT adapters exposes the merged baseline. Reference generation, IEM
denoiser probes, and NFT's KL reference all use this same baseline. Rollouts use
`old`; optimization updates `default`.

All generation runs without CFG (`guidance_scale=1`). Candidate and same-prompt
reference endpoints both use deterministic DPM2 with 25 steps. This is an
intentional NFT adaptation of RAM run 190607, whose generator used 20 steps.

## Candidate data flow

`DistributedPromptGroupBatchSampler` keeps a complete prompt group on one rank
(`flow_grpo/nft_creativity_runtime.py:23`). In the full two-GPU configuration:

- 48 distinct prompts are sampled per epoch, 24 on each rank.
- Each prompt produces 24 candidate endpoints.
- Sampling batch size is 6, so four consecutive batches form one complete group.
- Each epoch therefore has 1,152 candidates globally and 576 per rank.

The patched sampler returns clean latent endpoints directly when
`output_type="latent"`; it does not pass them through the VAE. The trainer
collates endpoints, prompt embeddings, pooled embeddings, and prompt strings,
then calls the reward synchronously (`scripts/train_nft_creativity_sd3.py:510`).
Synchronous evaluation is required because the reward temporarily disables NFT
adapters on the shared transformer.

## Same-prompt references

For each candidate prompt, 256 reference endpoints are generated by the frozen
baseline. Every reference uses the candidate's prompt but an independent initial
Gaussian latent. Seeds are a stable hash of base seed, epoch, prompt, and
reference index (`flow_grpo/creativity.py:1554`).

The implementation validates that all 24 candidates in a flattened group have
exactly one prompt (`flow_grpo/creativity.py:1190`). Statistics are created and
consumed inside that prompt group's loop (`flow_grpo/creativity.py:1476`), so
features from different prompts cannot enter the same reference mean.

With 48 prompt groups and 256 references, a full epoch generates 12,288
reference endpoints globally, or 6,144 on each rank. References are streamed in
batches of 2 and are not retained as a 12,288-image bank.

## IEM feature calculation

The schedule is a descending log-uniform sequence of 65 sigma boundaries,
giving 64 integration intervals (`flow_grpo/creativity.py:184`). The full preset
uses `sigma_min=0.009`, `sigma_max=1000`, as in the requested RAM comparison.
Gamma is `1 / sigma^2`, and interval widths are consecutive gamma differences
(`flow_grpo/creativity.py:211`).

Each noise table contains one IID Gaussian latent tensor for every integration
level (`flow_grpo/creativity.py:229`). Eight deterministic tables are available
per epoch. A whole 24-candidate prompt group receives one table; groups cycle
through the eight tables (`flow_grpo/creativity.py:1167`). The 256 references
for that prompt and all its candidates use the same assigned table, making their
feature distances comparable. Different levels within a table still use IID
noise.

For endpoint `x_0` and VE sigma, the implementation maps to rectified-flow time
`t = sigma / (1 + sigma)` and constructs:

```text
x_t = (x_0 + sigma * epsilon) / (1 + sigma)
```

SD3 predicts rectified-flow velocity `v = epsilon - x_0`. Therefore equation
14's clean prediction is `f(x_t,t) = x_t - t*v`, with the prompt supplied as
positive conditioning. The residual is `e_gamma = x_0 - f(x_t,t)`
(`flow_grpo/creativity.py:273`).

Equation 16 is represented by concatenating the weighted residuals over all
levels. To remain exactly comparable to the current RAM experiments, the weight
is `sqrt(delta_gamma / 64)` (`flow_grpo/creativity.py:325`). Thus current runs
use the interval average convention. Removing `/64` later would multiply all
squared IEM distances by the constant 64 when the level count stays fixed; that
change is deliberately not included here.

## Equation 21

Reference features are accumulated as only three quantities:

```text
M
sum_phi = sum_j Phi(x'_j)
sum_squared_norm = sum_j ||Phi(x'_j)||^2
```

The code computes:

```text
mu = sum_phi / M
v  = sum_squared_norm / M - ||mu||^2
reward(x) = ||Phi(x) - mu||^2 + v
```

See `flow_grpo/creativity.py:332`, `flow_grpo/creativity.py:372`, and the
same-prompt calculation at `flow_grpo/creativity.py:1674`. This is exactly the
mean squared feature distance from candidate `x` to all references. The final
`clamp_min(0)` only removes small negative roundoff from the mathematically
non-negative variance identity.

The feature calculation is under `torch.no_grad()`. In NFT the reward is a
sample-level scalar used to form advantages; gradients are taken through NFT's
denoising loss, not through the reward model.

## NFT objective and scaling

There is no RAM-style `reward_multiplier` in this run. The single IEM component
has weight 1.0 in `CreativityRewardSet` (`flow_grpo/nft_creativity_runtime.py:88`).
Advantages are standardized independently inside each 24-sample prompt group
because `sample.global_std=False`. A positive constant reward weight would
therefore cancel, apart from numerical epsilon and raw logs.

The two NFT coefficients are separate from reward scaling:

- `config.beta=0.1` mixes current and lagged velocity predictions in the NFT
  positive/implicit-negative construction (`scripts/train_nft_creativity_sd3.py:752`).
- `config.train.beta=0.01` weights the squared prediction KL to the merged frozen
  baseline (`scripts/train_nft_creativity_sd3.py:784`).

Training uses batch size 8 per rank and 72 training batches per epoch. With 24
trained rollout timesteps, gradient accumulation is `72 * 24`, producing one
optimizer update at the end of each epoch.

## Evaluation and resume

Fixed validation is implemented in `flow_grpo/nft_validation.py:20`:

- 30 balanced prompts: 15 basic and 15 imagination.
- A baseline panel is rendered before epoch 0.
- A separate panel is rendered after every completed epoch.
- Evaluation uses 40 DPM2 steps and guidance 1.
- Initial latents use RAM's stable SHA-256 prompt-seed rule
  (`flow_grpo/nft_creativity_runtime.py:74`), so every panel uses the same latent
  for a given prompt and different prompts receive different latents.

Every completed epoch is checkpointed atomically before evaluation
(`flow_grpo/nft_creativity_runtime.py:162`). A checkpoint includes both NFT
adapters, optimizer, scaler, EMA, global step, next epoch, all per-rank Python /
NumPy / Torch / CUDA RNG states, creativity reservoir state, resolved config,
and a standard exported `default` LoRA. `_SUCCESS` and `checkpoints/latest`
identify complete checkpoints. Resume restores this complete state at the next
epoch (`flow_grpo/nft_creativity_runtime.py:243`).

## RAM-aligned inputs

`sd3_iem_same_prompt_partiprompts_ram_aligned` is an opt-in comparison preset.
It aligns three inputs with RAM while leaving NFT's optimizer and 25-step DPM2
candidate sampler intact:

- Epoch prompt groups use the same one-file `BalancedPromptSampler` algorithm,
  seed `config.seed + epoch`, order, and distributed striding as RAM.
- Validation prompt selection uses seed `3_000_009`; validation latent seeds
  continue to use RAM's prompt-specific hash with base seed 0.
- IEM, CLIP, and DINO references are loaded from RAM's immutable cache. IEM
  consumes the exact BF16 endpoint latents, while CLIP/DINO consume the exact
  FP32 raw embeddings saved beside them.

The reader requires the cache `_SUCCESS` marker and validates its specification
hash, prompt-file digest, seed, resolution, reference count, baseline inference
steps, guidance scale, and encoder model IDs. It never silently falls back to
NFT generation when an aligned cache entry is absent or incompatible.

This aligns reference endpoints, not NFT candidate endpoints. RAM uses a
20-step Euler rollout and NFT uses a 25-step DPM2 rollout, so their final
candidate latents should differ even when a later experiment supplies identical
initial noise. Existing unaligned NFT presets still generate references through
NFT's sampler and retain their prior behavior.

On AirCC, select the aligned preset with:

```bash
sbatch --export=ALL,CONFIG_NAME=sd3_iem_same_prompt_partiprompts_ram_aligned,RUN_LABEL=nft_iem_ram_aligned experiment_scripts/run_nft_iem_same_prompt_full_aircc_b200_2gpu.sbatch
```
